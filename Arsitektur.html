How dynamic context routing works

Routing memilih jalur kerja, bukan hanya model AI.

Setiap permintaan melewati kontrol yang menentukan konteks yang dibutuhkan, sumber yang berwenang, tools yang boleh dipanggil, dan kapan perlu eskalasi.

Understand

Klasifikasikan intent, tugas, channel, dan hasil yang diminta.

Authorize

Verifikasi identitas, hak akses, tujuan penggunaan, dan batas data.

Discover context

Temukan sumber relevan: SQL, dokumen, vector, graph, atau API.

Select route

Pilih tool, model, workflow, dan urutan eksekusi sesuai policy.

Validate

Periksa bukti, aturan bisnis, konsistensi, dan confidence.

Respond / act

Kirim jawaban atau jalankan aksi; gunakan HITL untuk pengecualian.

Six reusable building blocks

Kapabilitas modular yang dapat dikombinasikan.

Satu use case dapat menggunakan satu blok atau menggabungkan beberapa blok sesuai kebutuhan.

01 / Interact

Conversational AI

Memahami pertanyaan dan konteks percakapan, menjaga konteks sesi, serta menyiapkan respons atau handoff ke proses berikutnya.

Input: chat, voice transcript, user context
Output: intent, response, next action
02 / Understand

Document Intelligence

OCR, ekstraksi, klasifikasi dokumen, validasi field, dan pengelolaan exception untuk data yang berasal dari dokumen.

Input: PDF, image, form, email
Output: structured fields, validation flags
03 / Analyze

Auto Insight & Reporting

Mengubah data terverifikasi menjadi analisis, ringkasan, laporan, dan visualisasi dengan definisi metrik yang konsisten.

Input: approved datasets, metrics
Output: charts, insights, report
04 / Execute

Workflow Automation

Mengatur urutan proses, branching, retry, SLA, approval, notifikasi, dan eskalasi sesuai SOP perusahaan.

Input: events, rules, task state
Output: completed task, status, audit
05 / Connect

Data Integration

Menghubungkan aplikasi internal, database, layanan eksternal, event, dan perangkat melalui API atau konektor terkontrol.

Input: authorized query / command
Output: data response, system action
06 / Direct

Intelligent Routing

Mengarahkan permintaan ke tim, queue, channel, atau proses yang sesuai berdasarkan intent, prioritas, SLA, dan kebijakan.

Input: intent, priority, context
Output: assigned route, queue, escalation
Real-world execution

Permintaan berbeda, jalur pemrosesan berbeda.

Contoh berikut menunjukkan bagaimana routing mengombinasikan building block dan sumber konteks secara selektif.

Scenario 01

Status klaim via WhatsApp

WhatsApp→Identity check→Claims API→Reply

Conversational AI memahami pertanyaan; routing memilih API transaksi sebagai sumber otoritatif. Workflow menangani eskalasi jika data tidak ditemukan. Vector search tidak diperlukan untuk lookup sederhana.

Scenario 02

Verifikasi dokumen pengajuan

Upload→OCR→Cross-check→HITL

Document Intelligence mengekstrak field; SQL/API memeriksa data; rules mengevaluasi kelengkapan. Kontradiksi atau confidence rendah diarahkan ke petugas.

Scenario 03

Analisis penjualan eksekutif

Portal→Semantic layer→SQL→Chart

Routing memeriksa akses dan definisi metrik, mengambil data terstruktur, lalu Auto Insight menyajikan grafik dan narasi dengan provenance. LLM membantu menjelaskan, bukan mengarang angka.

Security & governance

Context-aware bukan berarti akses tanpa batas.

Routing harus mengikuti izin, kebijakan data, otoritas sumber, serta kontrol tindakan. Keputusan sensitif dapat mensyaratkan persetujuan manusia.

Architecture principles

Gunakan teknologi yang tepat untuk setiap tugas.

Routing tidak memaksakan semua permintaan melewati LLM atau vector database. Ia memilih jalur yang sesuai dengan jenis masalah.

Structured facts → SQL / API

Untuk transaksi, status, angka, dan data yang memiliki sumber otoritatif.

Unstructured knowledge → Search / RAG

Untuk dokumen, kebijakan, panduan, dan pengetahuan berbasis teks.

Deterministic actions → Rules / Workflow

Untuk validasi, keputusan berbatas, proses yang dapat diaudit, dan aksi yang memerlukan otorisasi.

Bring architecture into practice

Mulai dari use case. Rancang jalur yang tepat. Perluas secara modular.

Petakan kebutuhan bisnis, sumber data, sistem yang ada, kontrol keamanan, dan kapabilitas yang diperlukan menggunakan unified architecture ini.
